# RXSTORM RX980 本地适配

基于 sharkfin 0.10.0，保留 GPL-3.0-or-later 许可。适配最初在本地 `rx980-local` 分支完成，现由独立仓库 `whyIMBA/rx980` 的 `main` 分支维护；上游基线为 `b36c790`。固件更新和云端服务不在本版本范围内。

## 硬件证据

| 项目 | 结果 |
| --- | --- |
| 测试日期 | 2026-10-18 |
| 有线 USB | `3151:4010` |
| 系统产品名 | `RX980 Gaiming Keyboard`，保留设备原始拼写 |
| 厂商 | ROYUAN |
| 识别指令返回编号 | 671 |
| 固件版本 | 5.05 |
| 协议族 | yc500，`0x89` 返回按键矩阵，`0x8A` 返回全 FF |
| 配置 | 三套，每套普通层和 Fn 层各 512 字节 |
| 实体布局 | 98 键，每键均有唯一槽位 |
| 出厂矩阵 | 上游 `keymap-evidence.json` 中 671/v505 的矩阵，与实机配置索引 1 的对应字节完全一致 |

物理键位和 HID 键码从本机原厂软件的 RX980 布局中读取。槽位由该设备自己的固件矩阵确定，并对照实机读回数据。未复制原厂可执行程序、图像或界面资源。

## 已完成的写入验证

每项均先读取原值，再写入不同值，读回比较，最后恢复并验证原值。

| 功能 | 验证范围 |
| --- | --- |
| 灯光 | 修改亮度并恢复，未验证所有灯效的视觉表现 |
| 配置 | 从配置 0 切换到 1 并恢复 |
| 普通层改键 | 数字键盘小数点，实机槽位 77，临时映射 F24 后恢复 |
| Fn 层改键 | 同一槽位，写入、读回并恢复 |
| 消抖 | 修改数值后恢复 |
| 休眠 | 修改 2.4 GHz 休眠秒数后恢复 |
| 宏 | 空闲槽位 49，写入 F24 按下/抬起序列，读回 256 字节并恢复。未触发执行 |
| 选项 | 切换 Windows 键锁定并恢复完整原始选项字段 |

最后比较了全部六层按键矩阵、活动配置和灯光，均与测试前一致。原始 HID 请求和回复保存在工作目录的 `reports/`，备份在 `backups/`，不提交到上游仓库。

## 本地修改

| 位置 | 修改 |
| --- | --- |
| 设备表及覆盖表 | 671 指定 yc500、98 键布局、已读回的消抖和休眠功能 |
| `Local98_RXSTORM_RX980.json` | 98 键几何位置及固定槽位 |
| 共享 `wire.rs` | 识别到 671 后，八种已验证设置指令发送完成后等待两秒，再允许后续通信 |
| 两个传输后端 | 记录识别编号，调用同一共享等待规则 |
| 共享 `ops.rs` | 自动识别系统的 GET 必须正确回显，才允许对应 SET |
| 设备页 | 隐藏设备不回答的自动识别系统选项 |
| 语言包 | 增加简体中文，未翻译的文案沿用上游英文 |
| `tools/core-check` | 直接引用共享源码运行核心测试，无需桌面图形依赖 |

初次写入测试在 300 ms 后读取到空回复；等待后读取正常，原始灯光已确认恢复。两秒等待下，八项测试均完成读回和恢复。该等待只针对已识别为 671 的设备，不改变其他型号和 GET 指令的节奏。

`GET_AUTO_OS 0x97` 在该固件上重放上一个回复，不代表支持自动识别电脑系统。界面隐藏该选项，后台再次校验，避免无效写入。

## 浏览器验证

在本机 Edge 中通过实际 WebHID 连接到 671，读取固件、当前配置、灯光、消抖、休眠和选项。按键与设备页面加载正常，无页面运行错误，且未显示不支持的自动识别系统开关。应用导出的三套普通层及三套 Fn 层逐字节等于硬件测试前备份。

`ui-smoke.json` 是实际浏览器连接结果；`ui-smoke-replay.json` 是使用已录制实机回复的只读回放结果，两者分开记录。截图以不带 `-replay` 的文件为实机页面。
